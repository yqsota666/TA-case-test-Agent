# Case 业务输出核对

已确认 Plan 中的业务预期不能由开户或申购回传代替。协议核对仍使用本 Case 的申请、TA 原件、显式同步记录与正式数据；协议之外的结果由用户补充，AI 对照已确认预期给出建议，最终由用户手动确认。

## 输入与接口

`GET /api/chats/:chat/cases/:case/result-review/business-output` 读取当前锁定 Plan 最新的业务输出。`POST` 同一路径接收精确对象：

```json
{"requestId":"UUID","planVersion":1,"sourceKind":"USER_RESULT","content":"业务输出或调用日志原文"}
```

`sourceKind` 必须为 `USER_RESULT` 或 `SYNTHETIC_TEST`。原文最多 32000 个字符。合成演练需要显著标明来源，不能当成外部真实业务系统或真实 TA 的结果。接口绑定鉴权工作空间、Chat、Case、锁定 Plan 版本，追加保存原文、SHA-256、提交者与时间，不覆盖历史。相同 requestId 同内容返回原记录，异内容拒绝。最终状态 Case、封存 Chat 不允许继续提交。

保存后仍由原 `POST .../result-review/evaluate {}` 核对。严格 Plan 的协议预期保持确定性比较；若存在业务预期且有结果原文，结果 LangGraph 的 compare_case_expectations 节点调用模型，explain_case_result 节点合并协议核对和业务建议。没有结果、引用无效、覆盖不完整或无法对应的业务预期仍保持待核对，不能确认最终结果。

## 模型与证据边界

每条已确认业务预期恰好对应一个业务核对结果；比较数量、字段与业务条件不预设。模型完整引用预期、引用业务输出中的连续原文，并指出一致、不一致或无法判断。系统检查引用来源及覆盖，模型负责语义解释，不能把结构校验当作业务正确性的数学证明。协议条件已由系统核对，不要求用户重复抄录 TA 字段。模型只建议，不计算或伪造实际业务输出，不修改正式资源或最终状态。

`businessChecks` 保存 scenarioIndex、expectedQuote、evidenceId、resultQuote、verdict、explanation。UNCLEAR、缺项、重复、外部证据、无效引用及不完整原始 TA 证据不允许终判。客户界面使用中文；这些技术键只用于接口和内部记录。

原人工终判接口与审计记录保留。确认时重新收集当前协议与业务输出，复核证据摘要、最新审阅、Plan 版本、权限与原件；补充新结果后旧审阅不能确认。正常终判需明确人工理由，模型一致建议不自动等于 Case 通过。已有 TA 失败依赖规则不变。

## 验证

通用单元覆盖 1、2、7 条业务预期、变化字段、非对比单条、缺失/重复/虚构引用、不明确结果、等待回传与损坏原件。真实 MySQL 测试在事务中回滚，覆盖跨账户拒绝、追加/幂等冲突、版本绑定、模型处理期间输入变化、旧摘要拒绝、人工确认及结束后拒绝写入。

验收调用使用 Sophnet DeepSeek-V4-Pro-0813；本地合成结果仅用于验证模型核对路径，不代表真实外部业务执行成功。

## 回滚与运行记录

核心核对改动、HTTP接入与前端组件分别提交。回退入口不删除已提交的业务原文或旧审阅；023表有引用记录后禁止直接DROP。回退核心代码会恢复业务预期待核对行为，不得因此改写已终判Case或重新生成既有正式资源。模型输出属于语义建议，引用与完整覆盖校验不是业务语义正确性的数学证明，最终仍要求人工核对。

本地最新四包常规复验共309项：298通过、0失败、11项MySQL opt-in默认跳过。本次业务结果MySQL专项另行启用执行，1通过0跳过。主流程经实际页面明确提交合成业务输出、模型核对、人工最终确认后，只读复核得到Case已通过且LangGraph CASE_FINAL；具体本机证据在`.context/business-result/`，外部真实业务引擎与真实TA不在本次验收范围。
