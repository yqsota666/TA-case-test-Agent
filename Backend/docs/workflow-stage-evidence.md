# 流程图的完成证据

`GET .../workflow` 和新的恢复响应附带 `proven`，用于界面展示，不能用于授权执行。该字段每次从鉴权范围内的已提交记录计算，不根据终态或节点序号猜测前面的步骤完成。

- `completedStages`：当前锁定方案已有实际文件时序；必需发送步骤已登记SENT、必需接收已显式应用/确认；当前方案版本有有效核对记录；以及真实人工终判记录，各自独立证明对应阶段。
- `notRequiredStages`：只有锁定方案明确NOT_REQUIRED时，文件定义和交换阶段才可表示不涉及。
- `partialStages` 与 `exchangeSteps`：逐步骤记录完成情况。PARSED不等于APPLIED，未执行的可选05不冒充完成，失败阻断的未来步骤仍未执行。
- `result`：核对是否有完成证据、是否有明确人工终判、历史终判值。人工终判需审阅记录有final_verdict和confirmed_at，且对应当前方案版本并与Case最终状态一致；Case单独PASS/FAIL不足以证明整个流程。

活动Case的核对记录还需当前证据摘要一致；同方案版本新增业务输出后，旧审阅不表示当前核对已完成。已封存Chat可证明已有历史核对动作，但未确认的记录不冒充最终确认。强制封存未执行Case不会把未来节点补成完成。

此接口补充不修改业务资源或已有审阅，不直接写旧checkpoint。运行中的工作流仍按原来的事务与checkpoint恢复逻辑同步；前端需要刷新取得新的proven。代码与前端映射可分别回滚，保留所有历史证据。
