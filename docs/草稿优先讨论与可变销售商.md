# 草稿优先讨论与可变销售商

本次解决首轮将大量可模拟细节反问用户的问题。讨论优先给可编辑条件；只追问影响测试方向、操作链或预期判断的关键业务分歧，信息足够时不提问。金额、份额、客户样例、业务日期等可模拟输入标为【模拟假设】，用户指定或纠正的条件优先。真实业务规则、外部TA结果和未知TA账号不能由模型假造。

## 实现

- 统一首轮、后续讨论、方案和准备数据的草稿规则。完整讨论一轮后允许整理待审阅方案，前端、LangGraph及持久化门槛同步；零轮仍拒绝。
- 每次讨论或整理方案通过已有工作空间鉴权读取最新销售商通道。候选与用户实际选择分开，代码不固定，也不从基金名称推断直销/代销。未选定时不阻止其他草稿条件准备，发文前仍须选择合法通道。
- 模型遗漏模拟日期标记时，方案节点自动修正一次，继续保留严格日期校验。日期证据允许明确标记的模拟假设，兼容逐文件和按申请/确认日期分组的表述；未标注的模型日期、用户取消/改期/日期待定仍拒绝。模拟回传日期只是安排，不是TA结果。
- 数据和预期两次按钮确认、协议校验及正式资源同步条件保持。01/03同包、OFI处理顺序与02/04回传分开；05按核对需要决定。没有改写已确认历史方案。
- 同步规范 Backend/docs/agent-langgraph-protocol-chain.md，避免旧版02之后才能生成03的描述误导后续开发。
