# 账户业务操作链

基线：codex/assistant-ui ed2f6f50，已接入最新追踪查询过滤3470dca0；独立分支 codex/account-operation-chain。

方案契约增加逐申请依赖，以已有 applications 为任务单的唯一来源，不另存重复的任务结构。每项具有稳定 key、账户/基金、发送步骤、协议字段及依赖申请的明确结果。新版本预期通过 applicationKey 精确绑定同日多笔申请。固定 LangGraph 调度节点读取持久化申请事实，仅选依赖满足且文件前置条件满足的任务；恢复仍用已保存申请和幂等申请号，不让模型在执行时重规划。文件时序与逐笔条件共同约束，不放宽已确认文件日期和批次。新账户交易必须依赖本账户开户确认。兼容旧 v1/v2 方案。

按现有协议目录校验操作并标示正式生效能力；本次正式写入支持开户、申购及赎回。赎回按实际确认份额扣减正式持仓，必须有足够已确认份额，可用/冻结未知时保留未知。其余业务不编造会计效果，方案标明当前限制。所有数据与确认继续受工作空间权限、双确认、交付/解析/显式同步约束。

界面沿用当前材质和方案侧栏，增加“任务单”页签，按依赖拓扑展示账户、动作、日期、前置条件和真实进度，输入字段与预期按需展开。使用中文业务语义，不展示内部步骤标识或状态枚举；历史方案也可读，不反写历史。方案确认前支持任务字段手动编辑及原有对话修改，任何业务变更形成新版本并重新双确认。

验证：变长链、多账户分支、同日重复申请、长内容、只读、缺失信息、循环/跨账户错误引用、失败不放行、幂等恢复、真实 MySQL 事务与实际 Sophnet 提案。TA 回传使用合成夹具，不冒充外部结果。回滚按前端、调度/契约、赎回写入的独立提交逆序撤销，数据库迁移029允许记录赎回024。代码回滚保留已有交易历史；存在024记录时禁止缩回数据库约束，不删除账本。
