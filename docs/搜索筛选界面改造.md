# 搜索筛选界面改造

## 验收连续修复：文件交换入口

用户截图指出普通“下一步是什么”后突然出现文件交换卡片。原显示条件仅依赖exchangePlan READY（表示方案中安排已完整），未检查方案锁定及草稿确认，且卡片渲染在全部消息之后。修复为与FileExchangePanel实际准入一致：方案LOCKED、草稿reviewStatus CONFIRMED、协议及文件安排READY才显示。入口绑定当前方案的结果消息，不再插到后续用户提问之后；旧记录没有对应方案消息时只在页头保留已具备条件的入口。

42项常规前端单测及构建通过。新增合成浏览器验收覆盖未确认、已确认、无需文件三种状态，并核对已确认入口位于后续提问之前；截图 `.context/catalog-design/exchange`。5210热更新，5199未替换，没有发送真实讨论、模型调用或改动业务状态。

基线：统一平台0878e534。分支codex/catalog-filter-design，独立功能树 `/Users/apple/.codex/worktrees/fixed-workspace-scroll/gf`。本地候选5210代理现有3106，不替换5199，不重启后端，不迁移数据。

## 调研与取舍

- [OpenStatus data-table-filters](https://github.com/openstatusHQ/data-table-filters)：候选搜索、多选和候选数量适合业务筛选。实际读取 `packages/registry/src/components/data-table/data-table-filter-checkbox.tsx`，对应树dd87f2770048f1b805d497f1c763794e060781c1。上游依赖TanStack provider和shadcn基础组件，当前平台为React/Vite、自有表格与主题，整套引入需替换状态层。本轮把该组件的候选搜索、多选逻辑适配为CatalogFacetOptions，查询仍由现有后端执行，保留MIT授权文件 `Frontend/src/openstatus.LICENSE`，没有安装新依赖。
- [tablecn](https://github.com/sadmann7/tablecn)：常用字段与复杂组合分层，排序、筛选分别组织。借鉴组织方式，不引入Next.js及其数据库层。
- [Supabase官方讨论](https://github.com/orgs/supabase/discussions/42461)：单输入混合操作、应用状态不清和窄窗口不可操作等反馈，促成本轮保留明确标签、应用按钮、已应用条件行和窄窗口验收。

原后端已有类型化字段、候选、AND/OR、范围和排序能力，无需修改。本轮不声称支持全部候选远程搜索：候选弹层只搜索已返回最多50项，明确提示可从高级条件直接输入其他值。

## 交互

搜索与来源在左，排序和常用查询在右。业务筛选独立一行，按实际表及queryFields显示相关字段；文件突出类型、方向、销售商、业务日期，申请突出状态、业务日期、基金等。不存在的字段不显示，不把案例特征固化进UI。

候选弹层可搜索、多选，日期可填单边或完整范围；点击应用才更新。已应用条件可编辑或删除，OR明确标记任一满足。复杂分组在高级筛选弹层，排序独立弹层。保存、加载及删除集中在常用查询；保留原浏览器账户隔离、20条上限和刷新恢复。

使用浏览器原生模态dialog约束焦点，支持Esc、关闭按钮和外点关闭，关闭后返回触发控件。弹层内容独立滚动，底部操作保留。既有主页面布局、材质、协议文件、确认/生成流程不改。
