# 数据页销售商配置

数据页新增独立“销售商”表，读取当前工作空间的真实 TA 通道，新增配置后直接供申请生成时选择。销售商名称、代码、TA 代码、协议版本和环境单独列出；支持新增、名称编辑、搜索和详情。代码以字符串保存，保留 005 等前导零。同一环境、TA、销售商组合不能重复。

配置直接复用 exchange_channels，避免单独维护一份与生成链路不同步的销售商名单。不新增数据库迁移。新配置继续按现有通道交付规则选取完整 ZIP 格式；这里没有改变 OFI/OFX 交付配置接口。销售商代码、TA、协议和环境创建后固定，仅允许修改名称，防止历史申请、文件与回传的归属被更改。需要另一组合时新增配置。

当前本地模拟账户的工作空间通过新增界面保存了 005 中国建设银行、227 广发基金、926 网商银行，TA 27、协议 22、LOCAL 环境。原 306 配置及历史申请保留。其他账户的工作空间不会自动被添加这三个销售商。本地新工作空间存在多个可选模板时不再失败或猜选默认销售商，可在数据页自行配置；仅单个明确模板时保持原初始化行为。

生成页的多通道选择显示销售商代码、名称、TA 和环境。既有申请已绑定的通道保持原归属，不能通过改名变更销售商。新 Case 应选择需要使用的销售商，再生成申请。没有自动确认业务草稿，也没有重新生成用户历史批次或投递真实 TA。

API：GET /api/data/tables/distributors 使用原数据表分页与搜索；POST /api/data/distributors 新建；POST /api/data/distributors/:id 修改名称。写接口校验会话、账户切换标识、同源 Origin、JSON 和字段；读写均按工作空间隔离。数据库唯一约束拒绝重复组合。

验证：后端常规 436 项中 416 通过、20 项 MySQL 按开关跳过；另显式执行 005、227、926 三项 MySQL 测试通过，全部合成测试业务记录回滚。测试经配置仓库创建销售商，再走准备、生成、完整 ZIP 保存链路，同时验证越权、重复保存与更名。前端 22 项通过，构建成功，保留原有 bundle 大小提示。界面验证新增三条、编辑保存、身份字段只读、重复保存失败保留输入、取消、Escape、搜索、清除和详情。390px 视口下页面宽度 390，无页面横向溢出。未调用真实模型，未 push 或创建 PR。

设计：沿用现有数据页表格、字体和颜色变量，让销售商配置与客户、账户、基金等数据保持一致；独立表签将通道身份从业务记录中分开；弹窗只放必要配置字段，减少表格内输入干扰。ENERGY 1 / RHYTHM 1 / MOTION 1，主视图焦点为记录表，操作色沿用产品变量，不新增动画或装饰。

界面检查：Hard Gate PASS（新增/编辑/取消/详情/搜索已点击，空表有固定列和暂无记录，错误保留输入，键盘 Escape 和390px验证）；Purpose Gate PASS（复用现有数据页样式，布局和颜色依据见上）；Liveliness PASS（沿用表格节奏、空白、操作色和现有产品特征）；Craftsmanship PASS（真实库内容、会话及工作空间隔离、测试/构建通过，未展示伪造业务结果）。截图和日志位于本功能树 .context/distributors。

本地回滚可单独撤销本功能提交；无需撤销表迁移。三条销售商配置是用户实际新增的业务配置，回滚界面不删除它们。
