# 平台补全界面规格

使用 finesse-term 将本轮口语要求整理为可实现界面规格，finesse-ui 延续现有光谱悬浮材质。主对话布局与方案样式保持；以下增量独立提交、独立回滚。

## 数据

左侧“数据”打开当前账户的全局记录。进入后隐藏左侧项目栏，内容使用页面全宽展示；此为内容区铺满浏览器，不是调用浏览器全屏。客户、账户、基金、持仓各独立整页，申请记录另页；一次只显示一张表。表头固定，表体上下滚动，宽表在自身容器内横向滚动，不撑宽页面。搜索与分页作用于当前表。不展示额外刷新按钮，不展示“草稿／正式数据”切换控件；后端仍保留草稿与正式数据的业务区分，移除控件不等于删数据或混淆状态。取消原先由代理自行增加的来源切换要求，默认展示范围随真实接口单独核对，不擅自改变业务含义。字段中文标签来自本地协议2.2，已有真实协议资料尽量完整展示，缺失值显示“—”。不展示数据库主键。可以从记录来源回到Case，保留对话输入。

## 文件

左侧“文件”汇总当前账户申请与回传原件，进入后隐藏左侧项目栏，内容全宽展示，不增加额外刷新按钮。搜索文件名、项目、Case、类型及通道。下载返回保存的原始字节。同一账户同文件名同摘要的中央收件与Case解析档案优先展示后者；尚未解析的收件仍可见。宽表独立滚动。

## 项目统一交换

确认方案和草稿后，申请准备等待项目其他活动Case确认。兼容申请按同通道、同业务日期、同实际依赖及文件类型合批。真实不同日期/依赖保留分批。文件交换卡片内显示中文等待状态，不显示步骤ID。

一份回传保留各Case原件及自身接收步骤。解析不生效；用户选择记录后一次明确同步，各Case联动在同一个事务提交。任何Case同步失败整体回滚，不静默部分成功；历史终态不重写。

## 05

仅当前已锁定方案确有05接收步骤时显示虚线接收框及解析对照。按当前方案的对应日期/接收步骤匹配，不猜日期。不规划05时不出现05模块。明确同步一次后更新正式余额；重复操作幂等，未知值保留空。

## 项目管理

对话中“项目管理”卡片打开普通详情弹窗。显示真实Case状态、关联复测与封存操作。失败Case保留只读历史并创建关联Case；已有复测提供查看入口。正常封存须所有Case结束，强制封存需原因。新轮次需明确确认保留正式数据，不暗示TA已重置。关闭弹窗恢复焦点，背景禁止滚动，键盘可操作。

## 验收边界

协议与API验证使用生产接口和真实MySQL，TA回传均为明确合成夹具，不能称外部TA结果。账号隔离服务端验证。首页/Plan不因本轮改动增加宣传文案或指标。研究预览及历史快照留在本地，不作为生产静态资源发布。

## 数据表结构补充（2026-10-08）

采用数据库客户端的网格浏览与单记录详情思路。客户身份、账户标识或基金标识优先于来源信息；字段数量按接口变化，不硬编码样例。完整协议字段保留。桌面固定首列与右端操作列，表头固定；表体在自身区域横向/纵向滚动，行高44px。窄屏不同时冻结两端以免遮住主体。

搜索作用于真实服务端目录，输入250ms后查询；无结果仍保留已知表头，提供清除搜索。读取期间保留当前表结构，分页显示记录范围与总数，仅超过一页才出现翻页按钮。金额、净值、份额右对齐，账号与代码作为字符串；时间中文显示，详情保留完整字段值与数字精度。全局页只读，不增加编辑功能。

点“详情”打开普通大小记录弹窗，字段名/值逐行对齐，长值换行、内容可滚动；关闭或Esc恢复操作焦点。文件下载固定在操作列。返回对话恢复原侧栏和输入区，不改变Case选择。首页与Plan不改。

本轮是展示结构调整，移除来源下拉没有授权合并草稿与正式资源。当前数据请求沿用原默认草稿范围；后端formal查询能力保留。全局真实正式资源的默认展示范围仍需后续单独对齐，不能将本轮视觉验收称为该范围已完整接入。

研究依据：DBeaver官方Data View and Format（网格/单记录视图及数值日期格式）、AG Grid官方Column Pinning（左右固定列）、TanStack官方Column Pinning Guide（同表sticky实现）。没有安装或宣称使用这些组件库；本轮在现有原生表格上实现相应交互。
