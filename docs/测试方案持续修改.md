# 测试方案持续修改

基线：5199 的 e0b217a7，功能分支 codex/editable-test-plan。

用户始终查看同一份当前测试方案，通过聊天或手动编辑更新。已有方案时，明确修改条件直接进入方案更新；仅询问、认可或暂缓修改保留原方案。内部保留版本和未完成状态，界面不要求用户经历“草稿转审阅”。

方案详情底部常驻确认区，依次确认准备数据和预期结果。缺失项、运行中、失败均显示真实状态。仅预期或证据变化且准备条件、操作、文件安排和数据完全相同时，沿用上次数据确认；其他变化重新确认。历史确认保留原人和时间，不能由模型补写。

第二次确认后锁定方案并准备数据，核对生成记录与确认定义一致后进入文件交换，不再要求第三次“确认草稿”。新增按方案授权的数据确认记录用于区分旧流程，已有锁定历史保持旧语义。生成失败或核对不一致停留在可重试状态，不能显示成功。准备数据不是正式账户或持仓，正式资源仍由回传同步。

进入执行后不修改原申请、回传或结果。方案持续修改限于两次确认完成之前；后续业务修改保留原测试并建立新的测试记录。原来的协议、同包01/03及OFI、跨Case合批和结果证据关联继续使用。
