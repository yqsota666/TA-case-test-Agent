# 数据与文件搜索筛选

实现基线：统一平台 `29c37109`；独立功能分支 `codex/catalog-query`，本机接回统一5199入口，不上传远端。

## 使用

数据页保留六张表。客户、账户、持仓可切换生成数据和TA回传确认后的正式数据；基金、申请记录、销售商沿用各自真实来源，不虚构正式基金目录。

两个页面共用快捷搜索、常用字段候选、筛选分组、多字段排序、已选条件标签、清空及保存查询。常用候选在当前其他条件范围内读取最多50个值及数量；更长列表可以用高级条件直接输入。文本支持包含、等于、前缀、排除、多值；数值支持比较和区间；日期支持比较和起止区间；缺失值单独查询。组间支持全部/任一满足，最多3层、40个节点，排序最多3项。空子分组明确拒绝，不当作全部匹配。

查询和总数在后端执行，按100条分页并追加唯一排序键；刷新与页面返回恢复已应用条件。常用查询最多20个，保存于此浏览器、按登录账户和数据表隔离，可删除；不会跨设备同步。关键词和业务筛选值不放入页面地址栏。关联导航地址仅携带公开项目、Case和批次标识。

客户等数据行可查看Case范围内文件；已有批次的申请进一步限定批次和文件类型。文件的“同批申请”限定真实批次、Case及对应01/03类型；无批次的05等记录仅提供“Case申请”，不冒充已逐条匹配的申请。合批申请文件保留多个Case关联，按任一Case可查询到同一条文件记录。回传档案从解析元数据按文件名取实际类型和日期，未知日期保留空值。

## 后端约定

前端使用只读POST：`/api/data/tables/:table/search`、`/api/files/catalog/search`。保留原GET兼容入口和GET下载。POST校验同源、账户及32KiB请求上限，条件在请求体传输，避免长中文查询超过URL上限。查询字段：`source`、`q`、`filters`、`sort`、`offset`、`limit`、`timeZone`；候选另带`optionsField`。响应包括原表格/分页字段和`queryFields`，不返回SQL表达式。

筛选结构示例：

```json
{
  "combinator": "and",
  "rules": [
    {"field": "ApplicationAmount", "operator": "gte", "value": "1000.00"},
    {"field": "business_date", "operator": "between", "value": ["2026-08-01", "2026-08-31"]}
  ]
}
```

字段和运算符由后端白名单决定，协议字段取自已支持的2.1/2.2定义。按字段提取JSON值，快捷搜索不会命中JSON属性名。代码/账号作为字符串保留前导零；数值左右两端均显式DECIMAL比较，不经过浮点数；零值不作为缺失值。业务日期按日期查询，生成/接收时间按用户时区的自然日起止转换为UTC，含夏令时边界。

所有分支、关联和候选统计均使用已认证workspace，客户端不能指定workspace。排序字段、方向、JSON路径均来自白名单；值参数化，LIKE通配字符转义。保留原始文件字节、下载校验、业务确认及生成流程。本次无需迁移，不修改真实业务数据，也没有模型调用。

## 验证与限制

后端全套、前端单测和构建通过；专项真实MySQL使用独立合成账户、125条客户、两Case共用批次、申请和回传档案，结束回滚。覆盖分页、金额/零值/大数精度、日期/夏令时、前导零、NULL、多Case及工作空间隔离。浏览器连接真实SQL合成夹具，验证快捷候选、条件分组、排序、保存/刷新、失败清空、正式来源、关联导航及桌面/390px/260px矮窗口。原六尺寸对话独立滚动回归通过。

本轮覆盖结构化元数据与已解析协议字段，没有提供任意文件正文全文检索。没有进行百万记录压测；现阶段沿用既有workspace及关联索引，后续按实际慢查询和执行计划增加索引，不宣称任意规模下的性能。原前端大包构建提示仍存在；旧SSR用例的已知基线失败没有混入本次修改。
